# Vulnerability Reports

Machine-generated by the AgentForge Documentation agent from confirmed Judge verdicts, each fix-validated by the regression harness. Demonstrated on the ephemeral vulnerable build (the live target is hardened — all held).

> ### Why these are readable
>
> This is the **disclosure lifecycle**, and the states are deliberately different.
>
> **While the target was live**, a vulnerability report was a working attack sequence against a
> running clinical system, so reproduction detail was operator-only: `/reports/*` returned 403 to
> anonymous callers, the `findings` array was withheld from the API, and every break-glass access
> was written to an append-only ledger. That control still exists and is still tested
> (`uv run pytest tests/test_web_gating.py`, and controls 18/19/32/35 in
> [../docs/GATE_LEDGER.md](../docs/GATE_LEDGER.md)) — it is a property of the dashboard, not of
> this directory.
>
> **Since 2026-07-23 the dashboard no longer withholds them either.** It ran for a day in the
> odd position of 403-ing documents that anyone could read in this repository, behind a login
> whose identity provider had been decommissioned along with the target — a gate guarding a door
> with no wall, pointing at a key that no longer existed. The deployment now sets
> `AGENTFORGE_PUBLIC_REPORTS=1`. That opens reads only; the mutating run trigger stays gated on
> every path, and re-gating a redeployment is removing one environment variable.
>
> **The target is now decommissioned and every defect below is fixed and regression-guarded.** A
> reproduction that points at nothing, for a bug that no longer exists, is no longer a weapon —
> it is the evidence that the work happened. Withholding it at that point would not protect
> anyone; it would just make the claims unverifiable, which this project treats as the worse
> failure.
>
> What is in these files, stated plainly so nobody has to take it on trust: **no credentials, no
> tokens, no host, and no real patient data.** The seeded records are synthetic throughout. The
> most "live" artefact here is a route path (`GET /week2/patients/1/reconciliation`) against a
> host that no longer resolves.
>
> The rule this follows: **gate while the system is live, publish once it is closed.** If the
> co-pilot is ever redeployed, the gate is what governs again — the deployment is the thing being
> protected, not the paperwork.
